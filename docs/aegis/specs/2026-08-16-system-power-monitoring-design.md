# 整机功耗监控设计规格

日期：2026-08-16
状态：已确认设计，待实现计划执行

## 目标
新增标准监控项 `SYS.Power`，让用户在主监控面板和任务栏查看整机软件估算功耗，并复用现有功耗趋势能力。

## 口径
`SYS.Power` = 整机功耗软件估算，**权威源优先**：

1. **电池放电中**（`AcOnline = false` 且放电功率有效）：直接使用电池放电功率。放电功率即整机直流功耗（已包含屏幕、主板、内存、存储等全部部件），是笔记本上最接近真实整机功耗的读数。
2. **PSU 总功耗传感器**（台式机 HID 电源，如 Corsair HXi/AXi）：PSU 总输出功耗本身就是整机功耗，直接使用。
3. **组件求和兜底**：`CPU.Power + GPU.Power + 其它可读功耗传感器`（主板/内存/存储/网络等硬件上的 Power 传感器，单项 200W 上限）。

规则细节：

- CPU 使用现有 CPU Package 功耗传感器；GPU 使用现有 GPU Board/Package/Core 功耗传感器选择逻辑；其它传感器由 SensorMap 统一收集（排除 CPU/GPU/电池，避免重复计数）。
- 电池放电路径与 PSU 路径直接采用有效权威值；组件求和仅作为无权威源时的兜底，不再用 `max(权威值, 组件求和)` 抬高结果。
- 组件求和按硬件设备选择单个聚合功耗传感器，优先 `Total`/`Package`/`Overall`，避免聚合值与分路值重复计数。
- PSU 只有明确的 `Total`/输出总功耗传感器才作为整机权威源；无法确认总功耗时回退组件估算。
- 只对有有效值的组件求和；全部无有效值时返回无数据。
- 各路径均有合理性区间过滤（电池 0.5~500W、PSU 1~1000W、组件合计 ≤1000W），防止异常传感器值污染。
- 结果单位为 W，并沿用现有功耗格式化、颜色和最大值保护（新增 `RecordedMaxSysPower` 记录整机功耗自适应上限）。
- 这是软件估算值，不等同于墙上插座实测功耗；不接入外部功率计或新增 PSU 采集链路。

## 展示与配置
- 新增 `SYS.Power` 标准监控 key。
- 默认 `VisibleInPanel = true`。
- 默认 `VisibleInTaskbar = true`。
- 现有设置迁移逻辑自动向旧配置补齐该项，并保留用户已有项目设置。
- 文案使用“整机功耗 / System Power”，相关说明明确“软件估算”。
- 纳入现有功耗趋势分类和历史记录键集合。

## 运行时边界
- `HardwareMonitor` 继续负责硬件刷新，不新增扫描器或独立刷新线程。
- `HardwareValueProvider` 是 `SYS.Power` 组合值的唯一取值 owner，消费已有 CPU/GPU 功耗值。
- UI、任务栏和趋势图只通过标准 key 消费该值。
- 不修改已有 `CPU.Power`、`GPU.Power`、`BAT.Power` 的行为。

## 验收标准
1. 新旧 settings 配置启动后都能出现 `SYS.Power`，且默认面板和任务栏可见。
2. CPU 和 GPU 都有值时，显示值等于两者之和，并显示 W 单位。
3. 仅一项有值时显示该项数值；两项均无值时显示无数据而非 `0W`。
4. `SYS.Power` 可在现有功耗趋势视图中选择并产生历史数据。
5. 任务栏与主面板显示同一指标值，不新增第二套计算逻辑。
6. 既有监控项、用户配置字段和用户历史文件保持兼容。

## 验证
- 运行项目现有测试或构建命令，至少执行 `dotnet build -c Release`。
- 对组合逻辑执行针对正常、单项缺失、双项缺失和异常值的回归验证。
- 发布前按项目既定流程提交、推送、发布并替换实际运行目录；若构建环境缺少 SDK，必须明确报告未完成项。

## 非目标与风险
- 不保证测量主板、内存、硬盘、风扇及电源转换损耗。
- 不把缺失组件静默当成 0。
- 主要风险是估算值被误解为墙插功耗，因此 UI 文案必须保留估算说明。
